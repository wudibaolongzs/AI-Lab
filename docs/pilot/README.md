# AI-Lab 小规模试用方案

本文件是待执行方案，不是学生研究结果。建议邀请5–10名自愿参与的初学者，由团队自行招募，不自动发送站外消息。

## 课堂功能试用前置

课堂工作台默认关闭，且本机尚未配置真实班级凭据。组织真人试用前按下面顺序做，任一步未通过就不要开始收集学生记录。

1. 跑本机端到端验收，确认角色隔离、跨班拒绝、幂等与重启持久化：
   ```bat
   cd /d F:\GPT\华为ict
   python -B tools\verify_classroom.py --json evals\classroom-acceptance-20261110.json
   ```
   退出码 0 且 0 项失败才继续；该结果是代码与本机存储证据，不是真人试用结果。
2. 由操作员在仓库外生成两个班级的凭证（每班一个教师、若干学生），不要把凭证写进仓库或聊天。命令见 [课堂工作台](../classroom.md)。
3. 分别用教师凭证与学生凭证核对：学生只能看到本人求助，教师只看到本班，跨班回复返回 404，学生调用教师接口返回 403。
4. 重启服务后重新读取教师端与学生端，确认任务、求助和回复仍在；再做一次数据库备份与恢复演练。
5. 试用期间只记录求助元数据与参与者自愿提交的内容；结束后按事先说明删除或匿名化。

真实试用结论至少记录：日期、参与人数、班级、任务版本、失败案例、未完成者。不能把自动化验收通过写成“课堂试用已通过”。

## 参与前说明
说明项目为教学原型、AI可能出错、退出不影响课程成绩。只使用自选匿名编号；不收学号、电话、邮箱。源码导出和课堂求助内容仅按参与者主动提交范围收集，保存路径和删除时间提前告知。默认不上传学生源码到模型。

## 一次15–25分钟观察
1. 记录参与者以前是否学过Python，分为没学过、学过基础、有项目经验。
2. 分配一题，先独立运行，观察能否读懂输入/期望/实际。
3. 参与者自行决定是否领提示，记录最高等级和对提示的评价。
4. 修正原题后，填写可选自述并独立完成固定变式验证。自述不自动评分。
5. 再做一个同概念不同输入的小任务，记录首次作答是否正确。
6. 有条件时隔日回访一次不展示提示的复测，不把当场记忆当长期掌握。
7. 询问最不清楚的文字、操作和失败反馈，各记录原话与问题。

## 记录表
使用 pilot-observations.csv；空白字段留空，不用0代替未知。
source填 local、agentarts、tencent 或 deepseek；模拟单列mock，不能与真实调用混合。
原题通过率、变式首次通过、最高提示等级分别统计，不算成一个“掌握分”。

## 对照与解释
第一轮用于发现可用性问题；样本少，不能宣称统计显著或普遍提升。
如果要比较教学效果，先设计难度相当的任务，平衡任务顺序，记录既有经验和额外帮助。
本地规则与AI同样本提示比较是工程质量评测，不等于真实学习效果试验。

## 放行要求
记录人数、任务版本、日期、观察过程、未完成者与失败案例。只在取得真实数据后填写结论。
原始观察与汇总分开保存，公开材料使用匿名汇总。研究结束按事先说明删除个人记录。
