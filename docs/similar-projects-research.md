# AI-Lab 同类项目调研与后续搭建建议

调研日期：2026-11-08。来源为公开官方文档、作者论文、仓库README与项目作者说明。未部署或审计第三方系统；功能描述不能直接当作运行、安全或教学效果的验证。

## 结论

“AI编程辅导、分层提示、不直接给答案”已有多个先例，不适宜作为唯一创新点。建议AI-Lab聚焦中文基础编程场景，形成“确定性判题证据—分层引导—学生解释—变式验证—可复核学习记录”的完整流程。该定位是基于调研提出的产品建议，尚未证明其独创性或教学效果。

## 一、可核实的先例

| 项目 | 资料类型与已读取内容 | 可借鉴点 | 与AI-Lab的取舍 |
| --- | --- | --- | --- |
| CS50 Duck | 官方产品文档、作者论文 | 引导学生找到答案；课程一致的教学行为；持续人工评审 | 学习提问方式和复核流程，不复制课程品牌或开放式聊天产品 |
| CodeAid | 作者论文摘要、作者GitHub README | 概念问答、伪代码、错误代码帮助、提示评价与追问 | 给现有提示加反馈和受限追问，保持判题权威 |
| CodeHelp | 作者论文摘要 | 通过提示策略保护教学目标，支持教师课堂使用 | 输出校验之外增加教学质量样本与人工复核 |
| SmartCode | GitHub README | 确定性判题、三级提示、理解问题、技能档案和推荐 | 参考模块边界；不照搬其技能分公式、扣分机制或执行器安全结论 |

CodeAid论文报告了12周、约700名学生的课堂部署，并分析使用记录、调查和访谈。这说明有真实课堂研究先例，不代表其效果可直接迁移到AI-Lab。CodeHelp论文报告52名学生、12周使用研究，同样不能用作本项目的成绩。

## 三、后续搭建顺序

### 第0阶段：完成原有验收，优先于扩展

1. 人工填写DeepSeek现有144个提示位置的复核项；原始报告不改，导入产生reviewed副本。
2. 华为配置可用后，单独采集AgentArts报告，记录工作流、模型、版本、调用编号和耗时。
3. 完成受控部署的HTTPS、网关鉴权、保护开关与外部访问验收。
4. 保持已有判题、保护、日志、主题和浏览器回归；不进行全面框架重写。

验收：报告来源可区分，评分完整，正常与故障回退都能复现；当前代码能力不重复建设。

### 第1阶段：理解验证闭环，建议3–5个开发日

先只做平均值题，再推广另外两题。

- 提示前可选填写“我认为哪里有问题”，不强制连续点击答题才能继续，避免阻塞新手。
- 通过后显示一个简短解释问题，例如给出新列表，让学生预测平均值并解释分母代表什么。
- 接着给一题人工编写、目标相同的变式练习；首次独立作答前不展示原题答案。
- 第一版用固定题库和确定性答案判定，不让模型自由生成带评分权的验证题。
- 记录初次作答、提示等级、修改次数与变式结果，将“原题通过”和“理解验证通过”分开呈现。
- 学生解释文本只能作为自述；未获得可靠评分前，不自动标记为掌握。

实现建议：题目数据增加learning_goal和固定follow_up定义；单独增加概念验证接口，旧/api/check、/api/hint契约保持兼容。验证答案不随题目列表一并发给客户端。

验收：原题4/4不自动等于理解；不看提示也能完成变式；错误输入、重复提交和切题不串记录。

### 第2阶段：记录与反馈，建议3–5个开发日

- 提示增加“有帮助、太模糊、接近答案、可能错误”四类反馈。
- 先保存到浏览器并支持带版本号的导出/导入；校验大小、结构、题号，不渲染导入HTML。
- 只有确认跨设备需求后再引入SQLite及身份方案，不仅靠前端用户名隔离数据。
- 事件至少关联题号、提交编号、提示等级、来源、反馈、是否缓存和验证结果。
- 源码和个人信息的持久化单独决定；继续保持默认不上云源码。

验收：重启/刷新后恢复，导出可重新导入；来源准确，异常数据不会破坏已有记录。

### 第3阶段：小题库与课程约束，建议1周

- 先扩展到8–12道AST兼容题，按总和、计数、平均值、数值表达式与边界检查安排学习目标。
- 每题包含正确解、典型错误、边界测试、三级提示依据和一题变式。
- 教学提示加入允许使用的概念、学生已学内容和本节目标，减少超纲解释。
- 暂不建设向量数据库；先用小型人工审核知识卡按题号/概念精确检索。资料规模与检索问题明确后再考虑RAG。
- 延后循环、导入等通用Python能力，避免先扩大安全边界。

验收：新增题目本地闭环完整；模型提示引用知识卡时可定位原文；扩题后评测样本版本独立保存。

### 第4阶段：教师最小工作台，建议1周，依赖身份与授权

- 只做班级任务、常见失败类型、提示反馈和待处理求助队列。
- 学生主动选择提交求助，由教师查看必要上下文；允许撤回，不自动向老师发送站外消息。
- 教师按班级授权访问，学生不能读取别人记录；求助单不默认附带全部源码。
- 先用简明“待处理—已回复”流程，不复制研究项目的多服务架构。

验收：学生求助、教师回复、学生复验可完整演示；越权测试通过。

## 四、效果评测该怎样改

- 工程评测继续用固定合成错误样本，评证据一致性、可操作性、答案泄露、延迟与回退。
- 学习评测另做：原题独立完成率、最高提示等级、相同概念变式首次通过情况；有条件再观察隔日不看提示的复测。
- 先招募5–10名学生做可用性试验。人数少时报告人数、任务、观察记录和失败案例，不据此宣称显著提升。
- 题目顺序、任务难度和既有基础会影响结果，需要记录；不能把“点击后通过”直接解释为教学效果。
- CS50改进论文中的持续人工评价思路值得借鉴；不急于微调，先积累经过人工审核的好/坏提示对。

## 五、建议用于参赛的定位

建议表述为：

面向编程初学者，结合本地判题证据和AgentArts分层辅导，通过解释与变式复验记录学生的修正过程，帮助教师发现仍未解决的概念问题。

这是一项拟实现的定位。当前源码并不已具备解释验证、变式题或教师工作台，材料中应按实际完成程度描述。
