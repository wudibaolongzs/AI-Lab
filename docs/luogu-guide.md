## 取得授权后的操作顺序
1. 自行向洛谷开放平台申请OpenApp，确认题面展示范围与评测计费规则。助手没有代发申请或购买额度。
2. 与平台确认结果查询接口的请求ID传递位置。官方OAS对 /judge/result 的id声明存在矛盾，当前客户端 ?id= 形式只是待核验实现。若实际方式不同，先调整luogu_client.py并补测试，不要直接打开开关。
3. 配置课堂独立学生凭据，见 [课堂说明](classroom.md)。仅学生能够提交和查看自己的远程记录，教师凭据不用于该入口。
4. 在私有.env或服务器环境配置以下变量，Token不发聊天、不写源码、不加Basic前缀：
```dotenv
LUOGU_ENABLED=0
LUOGU_OPENAPP_TOKEN=
LUOGU_DB=
LUOGU_PROTOCOL_VERIFIED=0
LUOGU_CONTENT_AUTHORIZED=0
```
LUOGU_OPENAPP_TOKEN填写平台提供的原始用户名:密码组合。LUOGU_DB可填私有SQLite绝对路径，默认data/remote.sqlite3，与题库/课堂数据库分开。
5. 只有协议核验通过、授权额度明确后才把PROTOCOL_VERIFIED和ENABLED设为1，重启。内容授权开关与评测授权是两件事；获得内容再分发许可后才可开启CONTENT_AUTHORIZED。
6. 先用少量代表题进行Python和C++真实试交，覆盖正确、错误与编译失败，记录题号、语言、代码版本、本地任务号、上游requestId和实际费用。未经确认不对300题批量试交。

## 学生提交与结果
网页输入本人的课堂凭据，只在当前页内存中保留；刷新或退出会清除。输入完整的标准输入输出程序，不是单个教学函数，当前界面与服务器限4000字符。
每次新提交需要确认源码将上传洛谷。每种语言分别保存本机草稿，导出文件可能包含这些草稿，但不包含凭据。
页面最多自动刷新120秒，之后可手动刷新。评测完成不等于通过；未知状态不会推断为Accepted。答案错误不会生成虚构隐藏用例。
若显示“提交结果不确定”，可能是上游已收到但本地没拿到确认。不要换编号自动重交，应由管理员核对，避免重复计费。

## 保护与存储
同一逻辑提交编号重复请求返回原记录，更改代码/题号/语言后复用编号返回409。
服务只保存学生归属、源码摘要、题号、语言、请求编号和结果，不保存原始程序正文。编译诊断可能含上游提供的代码片段，应按课堂记录管理。
每个应用进程最多2个并发上游请求；每名学生滚动1小时10次、全局滚动24小时50次，配额存SQLite。单进程部署，不能以多个进程共享数据库来宣称网络并发仍为全局2。
身份错误、上游额度不足、限流分别显示；没有自动充值和自动重投。应用限额不替代平台账户额度控制。
