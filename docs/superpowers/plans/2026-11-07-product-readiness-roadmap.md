# 智学工坊 AI-Lab 后续建设计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将本地演示原型逐步完善为真实 AgentArts 参赛作品、小范围试用服务和可持续维护的教学产品。

**Architecture:** 先保留现有单页前端、Python 标准库 HTTP 服务和受限 AST 判题器，补足真实云端证据、前端回归和额度保护。多人试用时再加入 HTTPS、访问控制与存储，通用执行器独立隔离，避免在主服务中执行任意 Python。

**Tech Stack:** 当前 Python 3.9+ 标准库、HTML/CSS/JavaScript、unittest、GitHub Actions；浏览器回归建议引入 Playwright 作为开发依赖，存储先选 SQLite；生产服务与代理选型到部署阶段确定。

**Spec:** `docs/product-readiness-scope.md`。

## 约束

- 所有工期为 2–3 人基础团队的建议安排，不是交付承诺；账号申请和试用招募单独计时。
- 真实调用、模拟链路、本地规则必须分别标注。页面出现 AgentArts 字样不足以证明是真实云端。
- 不提交真实 Key、`.env`、学生个人数据。云端输入继续排除源码。
- 首阶段不更换整个前后端框架；循环、导入、属性访问仍受现有 AST 边界约束。
- 新增功能先明确验收场景，再增加必要测试，完成后独立提交；不以新增页面数量代替可用性。
- 本计划只新增文档，不执行云端发布、公开部署、许可证选择或源码上传。

## 完成顺序与阶段门槛

| 阶段 | 建议时间 | 产出 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| A 工程与真实链路 | 第 1–2 周 | 可回滚基线、真实云端演示、配对评测 | 工作流与请求可关联，质量评测完成 |
| B 稳定与参赛交付 | 第 3–4 周 | 页面回归、额度保护、演示包与材料 | 正常/异常均可稳定演示，版本可复现 |
| C 小范围试用 | 第 5–6 周 | HTTPS、邀请访问、日志与备份、试用反馈 | 安全门槛、恢复演练与小规模负载通过 |
| D 教学功能 | 第 7–8 周起，按需求拆分 | 数据同步、题库、教师视图 | 每项有真实需求与独立验收，不强行同时做 |

第 1–4 周结束即可形成参赛版；不要求等教师端和完整账号系统全部完成。

## Task 5：调用缓存、并发与额度保护（试用前 P0，2–3 天）

**文件：** `app.py`、`agentarts.py`、新增保护模块及 `tests/test_hint_limits.py`；必要时更新 `.env.example` 与 `tools/start.py` 的允许配置集合。

**接口约束：** `/api/hint` 仍返回现有字段；限额错误返回结构化信息；本地回退保持同级且原因可识别。

- [ ] 先增加重复点击、并发相同请求、不同等级、源码变化、失败恢复的测试。
- [ ] 增加有容量和 TTL 上限的内存缓存；键至少包含题号、源码摘要、提示等级、题库/提示词或工作流版本，原始源码不写缓存日志。
- [ ] 相同提交和等级在缓存有效时复用成功提示；同一用户连续获取三级仍可能需要 3 次不同等级调用，不能宣传为一次。
- [ ] 对同时到来的同键请求合并处理；短暂错误不长时间缓存，恢复后能重新尝试。
- [ ] 云调用设全局并发上限，试用初始建议 2；排队有长度/等待上限，满载时明确回退或限流。
- [ ] 服务端按邀请会话或用户设速率限制，初始可设每分钟 6 次新云调用；IP 仅做辅助，防止同一校园网络误伤。
- [ ] 失败达到阈值暂时熔断，冷却后少量探测；默认不盲目重试，只有确认上游幂等和计费语义后才考虑一次有限重试。
- [ ] 在应用与云账号分别设置可用的调用量/费用告警与停用开关；进程内计数重启会丢，不可单独充当硬费用上限。
- [ ] 云端范围开关拼写错误应提示配置错误；当前未知列表会退回全部题目，应在此阶段改为保守失败并补回归测试。

**验收：** 并发超过上限仍能判题；同键并发只调用一次上游；不同题/等级不串缓存；超限与熔断有可解释结果；无凭据和源码日志。

## Task 7：安全的小范围共享部署（P1，2–4 天，依赖 Task 5）

**文件：** `app.py` 或选定的服务入口、新增 `deploy/` 配置、`docs/local-deployment.md`、权限与代理测试。

- [ ] 先确认目标是同 Wi-Fi 演示还是异地试用；同 Wi-Fi 已有参数支持，公网才需要本任务的完整方案。
- [ ] 初期用受控邀请入口或网关鉴权，HTTPS 终止在反向代理；Key 只在服务器配置。
- [ ] 保护页面和全部 API；仅前端隐藏按钮不能构成授权。会话 cookie 需 HttpOnly、Secure、适当 SameSite，并处理 CSRF/Origin 边界。
- [ ] 明确代理转发的 Host 与端口；当前白名单按服务端口生成，外部 443 到内部 8000 需设计规范化转发，不能简单允许任意 Host。
- [ ] 限制代理可信来源；不盲信客户端 `X-Forwarded-For` 来做限流。
- [ ] 采用受维护的 HTTP 应用服务或网关承接公网请求；现有 ThreadingHTTPServer 继续用于本地开发，不直接当公网成品入口。
- [ ] 配置启动自恢复、依赖锁定/声明、私有网络端口、最小访问日志和保留周期；容器化可选，不作为“已部署”的充分条件。
- [ ] 做 10 个并发用户的判题/提示/慢请求混合测试；云端负载先用模拟运行时验证，避免无控制地消耗额度。

**验收：** 未授权请求被拒绝；HTTPS、过期会话、Host 拒绝和代理头伪造有测试；过载不拖垮本地判题；故障重启可恢复。

- [ ] 先扩到 8–12 道与现有 AST 能力兼容的题，而不是一次追求几十道。
- [ ] 每题写清学习目标、输入边界、签名、示例、典型误区和三级提示依据。
- [ ] 为每题建立正确解、边界用例、典型错误和无效代码测试；所有云端失败证据来自实际判题。
- [ ] 新题同时补本地规则、模拟输出和评测样本；报告注明样本集版本，旧 72 对保留历史意义。
- [ ] 当前用例都可见，定位为练习反馈；如增加考试/计分，另设计隐藏用例，禁止把其内容通过提示泄露。

**验收：** 正确解全部通过，预置错误稳定触发对应证据；单题可以离线完成教学闭环。

## Task 12：教师端与班级任务（P2，约 1–2 周，依赖 Task 10）

- [ ] 先只做班级邀请码、布置练习、完成概况、常见错误与提示使用汇总。
- [ ] 教师仅访问自己班级的授权数据；学生不可读取他人记录，后台不能只靠页面路由隐藏。
- [ ] 显示记录来源与更新时间；默认使用汇总信息，减少暴露学生源码和个人信息。
- [ ] 试用教师确认指标能支持一次具体教学决策后，再扩展批改或教学建议。

**验收：** 完成“布置 → 学生练习 → 教师查看汇总”的完整流程，跨班级越权测试通过。

## Task 13：通用 Python 执行与 MCP（P3，按需求另行估算）

- [ ] 只有当教学需要循环、分支等能力时才扩展执行器；当前白名单是明确产品边界，不能直接替换成 `exec`。
- [ ] 独立执行进程/隔离服务，设 CPU、内存、运行时间、输出、文件和网络限制；容器本身不是全部安全措施。
- [ ] 增加无限循环、超大运算、文件读取、网络访问、跨任务数据残留和逃逸尝试测试。
- [ ] 有具体工具调用需求再接 MCP；工具最小授权，学生输入和模型输出都视为不可信，不赋予任意本机命令权限。

**验收：** 隔离与资源限额经过专门审查后才接到主服务；这两项不阻塞首轮参赛交付。
