# 列表题提示对照评测

[固定样本](samples.json)由 24 条合成提交组成：平均值题 12 条（分子、分母、硬编码、运行错误各 3 条），总和题和计数题各 6 条（数量混淆、结果偏移、硬编码、运行错误、数值超限）。每条都带题号 `exercise`、首个失败用例 `case_id` 和诊断类别 `diagnosis_kind`，都能被本地判题器执行并触发失败。每条样本取三级提示，共 72 个评测位置。样本与判题器的一致性由 `evals.run` 在采集时逐条复核，对不上就直接报错。

在项目根目录运行下列命令可重新采集本地基线。报告中的耗时来自 `perf_counter`，包含每个等级独立执行一次本地判题。新采集的报告 `review` 全是 `null`，需要重新打分；先用 `--against` 比对旧基线，确认 72 条本地文本逐条相同后，旧打分可以按 `(sample_id, level)` 直接续用，只有措辞变了的样本要重打。本轮总和题与计数题的 36 条就是这样新打的，平均值题的 36 条逐字未变、沿用原分。

```powershell
python -m evals.run --output evals/local-rerun.json
```

配置并启动可调用 AgentArts 的 AI-Lab 后，用下列命令采集配对数据。工具只访问本机的 `/api/hint`，每个评测位置调用一次，没有自动重试。记录的接口耗时包含本机 HTTP 往返和后端处理。

```powershell
python -m evals.run --compare-port 8000 --output evals/paired-results.json
```

报告按样本、等级配对，包含判题证据、提示、来源、耗时及接口请求编号。汇总分别计数云端提示、本地回退和接口错误。回退和错误仍保留在采集分母中，提示质量比较只使用获得真实云端提示的有效配对。模拟环境的结果单独保存并注明来源。发布后可在报告中补记所用模型、工作流版本及采集日期。

## 评分规则

逐条阅读相同样本和等级的提示，对每侧独立评分。结果写入报告中的 `review` 字段，`true` 表示符合该项描述，`false` 表示不符合，`null` 表示待复核。

| 字段 | 何时记为 `true` |
| --- | --- |
| `evidence_ok` | 指向实际失败的用例，所述输入、差异、异常和行号均有证据支持。证据不足以唯一确定根因时，提示使用待排查的表述。 |
| `actionable` | 对该代码提出符合提示等级、可以立即执行的下一步。一级给出可检验的概念问题，二级给出可核查的位置或量，三级给出修复方向或复验步骤。 |
| `answer_leaked` | 直接给出完整正确函数、可直接复制的正确返回表达式，或提供足以直接替换提交的等价答案代码。 |

每项按已评分提示数给出分母。对配对结果，另外按实际获得云端提示的配对数分别汇总两侧得分。延迟使用中位数，回退和接口错误单列。

## 复核统计

上面的分子分母由 `python -B -m evals.score` 重算，不再手数。它逐条读 `review` 字段，按题项给出分子和已打分母，列出仍未复核的位置，同时检查报告有没有和产品规则打架：回退提示必须等于同级本地提示、云端提示必须是单行 240 字以内且不含可复制答案、`case_id` 必须取自失败用例、命中云端必须带 `request_id`，`summary` 里的每个数字也重新数一遍。

```powershell
python -B -m evals.score evals/local-baseline.json
python -B -m evals.score evals/paired-results.json --against evals/local-baseline.json --require-complete
python -B -m evals.score evals/local-baseline.json evals/paired-results.json --json evals/review-summary.json
```

`--against` 用来确认两份报告的本地侧文本逐条相同：相同就说明样本集和判题器没变，两侧可比，待复核清单里本地那一半可以直接沿用基准报告的打分；出现差异时按不一致失败，因为此时配对已经失去意义。`--require-complete` 在仍有位置没打满三项时失败，适合写提交材料前跑一次。退出码 0 表示一致，1 表示不一致或未复核，2 表示报告结构不对。`--json` 写出的统计文件是派生产物，可以贴进提交材料，但不必入库。

当前四份报告的复核结果：本地基线 72 条全部复核，`evidence_ok` 72/72、`actionable` 72/72、`answer_leaked` 0/72；接口回退报告与模拟配对报告结构自洽，但前者一条云端提示都没有、后者按约定不计入质量比较，两者的云端分子仍是 0/0；真实 AgentArts 配对报告见下节。

## 本地实测记录

[本地基线原始报告](local-baseline.json)收录 72 条提示。平均值题的 36 条沿用了此前的固定样本与措辞，逐条比对与上一份基线完全相同，已打的分可以直接续用。总和题与计数题的 36 条是本轮新增，措辞经过两轮复核：首轮发现第 1 级把「相加结果还是元素个数」这类具体猜测写进了提示，而偏移、硬编码样本的实际值既不是相加结果也不是个数，证据并不支持这个前提，于是改成让学生手算两个量再回头看返回值更像哪一个——与平均值题已复核过的写法一致。第二轮在页面上逐条读提示时发现，数值超限用例的「实际」一栏渲染成 `—`，第 3 级再说「看返回值比它大了多少倍」就指向了一个学生看不到的数，于是改成「看你的式子算出的结果比它大了多少倍」，让学生自己算一遍再对照；这两条分别对应 SU6 与 CO5 的第 3 级，其余 70 条文本不变。改后 72 条全部为证据一致、可操作、无答案泄露，中位耗时 0.036 ms（上一份基线是 0.034 ms，本机判题耗时本来就在微秒级抖动）。

[本地接口回退报告](local-fallback.json)记录未配置工作流时对 `/api/hint` 的 72 次调用，全部返回与本地判题一致的提示，接口错误 0 次，中位耗时 14.832 ms（含本机 HTTP 往返；上一份采集是 1.066 ms，差值来自本机回环与进程调度抖动，不是产品变慢）。该报告采集时默认云端范围只含平均值题，因此平均值题的 36 次回退原因记 `not_configured`，总和题与计数题的 36 次记 `local_exercise`；现在默认改为三道题都走云端，重新采集时三题都会记 `not_configured`。真实云端记录见下节。

## 模拟运行时配对记录

[模拟配对报告](mock-paired-results.json)来自 `tools/mock_agentarts.py`，用 `python -B tools/verify_agentarts.py` 采集：72 个位置全部标记为云端来源，接口错误 0 次，本机回放的中位耗时 16.822 ms（同一套链路前两次采集分别是 2.022 ms 和 15.947 ms，抖动主要来自本机而非模型）。脚本拼装的提示与本地规则同步修订，总和题数值超限的第 3 级也改成让学生对照自己式子的结果。它验证的是调用链路、输出校验与回退逻辑，提示文本由脚本拼装、耗时来自本机回放，**不计入云端证据**，也不参与提示质量比较。报告首部的 `note` 字段记录数据来源；`--note` 参数可为任何一次配对采集补注来源，真实云端采集时应写明工作流版本、模型与日期。

## AgentArts 真实云端配对记录（2026-11-10）

[真实配对报告](paired-results.json)由 `python -B -m evals.run --compare-port 8031 --timeout 70` 采集，24 个固定样本 × 3 级共 72 次调用，未启用自动重试：

- 命中云端 67 次，回退 5 次，接口错误 0 次；云端中位 9.765 秒、P95 28.777 秒、最大 36.586 秒。
- 5 次回退全部是 `workflow_failed` / `AgentArts.102056`，失败节点为诊断或教学提示；不是超时，也不是本地规则错误，回退路径按设计生效。
- 本地 72 条沿用本地基线已复核打分；云端 67 条由 AI 助手按评分规则初筛，结果为 `evidence_ok 46/67`、`actionable 51/67`、`answer_leaked 0/67`。该初筛**不是队员人工复核签字**，提交材料前必须逐条确认。
- 复核表为 [agentarts-review.csv](agentarts-review.csv)。人工确认后重新执行 `python -B -m evals.review import` 再跑 `python -B -m evals.score ... --require-complete`。
- 采集时服务端使用 `AI_TIMEOUT=60` 并关闭进程内频率保护（`AI_HINT_PROTECTION=0`），否则 60 秒 6 次的限制会让采样自身触发 `rate_limited`。产品默认仍是 8 秒与保护开启。
- 网页侧 9 个位置（三题三级）另见 [agentarts-web-20261110.json](agentarts-web-20261110.json)，全部标记 AgentArts，三题正确写法均 4/4；API 侧 9 条见 [agentarts-acceptance-20261110.json](agentarts-acceptance-20261110.json)。
